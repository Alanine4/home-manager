# Home Manager 🏠

> 家里有什么、还要买什么、今天能做哪道菜。单个 HTML 文件，不用注册，
> 数据默认只留在你自己的设备上。

**在线体验：** https://alanine4.github.io/home-manager/ ｜ **English:** [README.md](README.md)

---

## 这是什么

合住的人常常重复买同一样东西，忘记柜子里已经有了，做到一半才发现缺料。这个应用
管三件事：家里有什么、还要买什么、用现有库存今天能做哪几道菜。

它就是一个 HTML 文件。打开就能用，数据存在浏览器里。填个 AI Key 可以拍小票录入和
自然语言输入，配上 Firebase 可以多设备同步——两样都是可选的，不填也不影响使用。

## 怎么用

### 打开网址就行

https://alanine4.github.io/home-manager/

手机上加到主屏幕，看起来用起来就跟一个 App 一样，而且**装完之后断网也能用**。

- **Android：** Chrome 打开 → 菜单 → 添加到主屏幕
- **iOS：** Safari 打开 → 分享 → 添加到主屏幕
- **Windows / Mac：** Chrome / Edge 打开 → 地址栏右侧的安装图标

数据存在你自己设备上。不主动配置同步，就什么都不会离开浏览器。

### 或者把仓库下下来，直接双击 index.html

也能用，样式和界面都正常。但 `file://` 下浏览器不允许注册 Service Worker，
所以装不了 App、也没有离线缓存；摄像头和麦克风的权限也普遍受限。
想要完整功能，用上面的网址。

## 功能

### 🛒 购物车
- 按商店（Colruyt / Carrefour / Lidl）或分类分组
- 勾选已买 → 一键批量入库存
- AI 自然语言输入（「我要买番茄和猪肉」）

- 分类管理，支持折叠 / 排序 / 置顶
- 条形码扫描自动录入（Open Food Facts 数据库）

- 食谱库，自动显示当前库存能满足几种食材

### 🏠 家居必备
- 独立管理洗护 / 清洁 / 家居用品，与食物库存完全分开
- 低库存自动提醒

  Kimi、智谱 GLM、MiniMax、Mistral、Groq、OpenRouter、硅基流动

- 自由对话，可直接操作数据（加购物车、保存食谱等）

### 🔄 多设备同步（可选，默认关闭）

- 房间码机制：两人共享同一个数据空间
- 操作历史记录 + 一键撤销

## 数据存在哪

默认全部在浏览器的 localStorage，包括你的 AI Key 和 Firebase 配置。
不上传、不进仓库、不进同步的数据里。

**这也意味着：清掉浏览器数据 = 清掉你的库存。** 目前唯一可靠的备份手段是
**设置 → 数据管理 → 导出数据**，定期存一份 JSON。

几个已知会丢数据的情况：
- 手动清浏览器缓存 / 站点数据
- 换浏览器、换设备
- iOS 上长期不打开 Safari，系统可能自动清掉网站数据

自动备份还没做，[ROADMAP.md](ROADMAP.md) 里排在第 2 项。

## 云同步（可选，默认关闭）

不开这个，应用一切正常，只是不跨设备。开了才需要 Firebase。

1. 去 console.firebase.google.com 建项目，加一个 Realtime Database
2. 在项目设置里复制网页应用的配置
3. 回到应用，**设置 → 云同步**，整段粘进去
   （JSON 或控制台给的 `const firebaseConfig = {...}` 都认）
4. 把仓库里的 `database.rules.json` 粘到 Firebase 控制台 → Realtime Database →
   规则，发布
5. 在其他设备上重复第 3 步，然后把**房间码**发过去

**Firebase SDK 只在你粘了配置之后才加载。** 没配置的话，页面从打开到关闭不会向
第三方发出任何一个请求。

配了同步但想临时用纯本地（比如在别人电脑上）？网址后面加 `?mode=local`，
这一次就不连云，配置照样留着。

配置存在浏览器的 localStorage 里，不进仓库，也不进同步的数据。因为你一行代码都
没改，以后拉上游更新不会冲突。

## 技术与边界

**技术栈**：原生 HTML / CSS / JavaScript、Tailwind CSS、Firebase Realtime Database、
Open Food Facts、BarcodeDetector API、Web Speech API、GitHub Pages。
一个 HTML 文件加 `vendor/` 里一个 Tailwind，没有构建工具。

**明确边界**：

- **房间码是保护你数据的唯一一道门。** 任何知道码的人都能读写那个房间，没有踢人、
  也没有撤销的办法。好消息是别人列举不出有哪些房间，所以只要码不外泄就是安全的。
  把它当密码看：别截图发出去，别贴在公开的地方。
- AI Key 和 Firebase 配置存在每台设备各自的 localStorage 里，既不同步也不进仓库，
  每台设备都要各填一次。
- 应用跑在浏览器里，AI 服务商的接口必须返回 CORS 头才能用。上面列的都可以，
  只有一个例外：OpenAI 的 `/chat/completions` 不返回，浏览器直连会失败。
  想用 GPT 就走 OpenRouter 转发。
- **同步是整份数据推送，不是逐条合并。** 两个人同时改同一样东西，后保存的会覆盖
  前一个。日常买菜够用，高频并发编辑不行。
- localStorage 不等于备份，请定期导出。
- 条码扫描依赖浏览器的 `BarcodeDetector`，目前 Chrome / Edge / Android 可用，
  Safari 不支持。
- 语音输入依赖 Web Speech API，需要联网——浏览器会把音频送到厂商服务器识别。

## 常见问题

**一定要联网吗？**
不用。加到主屏幕打开过一次之后，断网照常用。只有 AI 功能和云同步需要网。

**一定要填 AI Key 吗？**
不用。手动录入的功能全都在，AI 只是让录入快一点。

**Fork 之后会连到你的数据库吗？**
不会。仓库里没有任何 Firebase 配置，你的部署只会连你自己填的那个。

**换手机 / 换电脑怎么办？**
设置里导出 JSON，在新设备导入。或者开云同步，两边填同一个房间码。

**房间码泄露了怎么办？**
在设置里换一个新房间码，把数据推过去。旧房间的数据还留在云端，但你不再用它了。

**为什么不做账号系统？**
因为那需要一个我来维护的服务器，而这个应用的全部意义就是不需要。房间码是在
「不要账号」和「能两个人一起用」之间的折中。等真有人用了会重新考虑，
理由和取舍写在 [ROADMAP.md](ROADMAP.md)。

## 参与

欢迎 issue 和 PR。改动前有三件事值得知道：

- Tailwind 放在 `vendor/` 里而不是 CDN，直接写类名，没有编译步骤，断网也不裂。
  往 `vendor/` 加东西必须同时加进 `sw.js` 的 `SHELL` 清单，否则离线时会缺文件
- 拼 HTML 时用户数据必须过 `esc()`，事件处理器参数用 `jsArg()`
  （见 `index.html` 顶部的工具函数）——漏一处就是一个 XSS
- 新增 AI 服务商只要往 `PROVIDERS` 注册表加一条，不用碰调用逻辑
